衔接说明（放在第 3 周日志之前）

第 2 周以两个结果收尾：分组选择没有优于逐块选择（零结果），以及基线仍接近随机，因此选取策略缺少可用的模型侧比较。第 3 周因此同时换了两件事，并在这里先说清楚：模型换成冻结的预训练 Qwen2.5-Coder-3B-Instruct，任务换成 1 跳、距离可控的程序。三点：

1. 先在新模型上重测第 1 周的三跳任务，结果是随机水平（整体 15%，Wilson 7–29%，n = 40；按源码长度 7–30%）。它保留为"难任务切片"，绝不用于比较注意力模式。

3. 所有比较都在同一份 checkpoint、同一个提示、同一个读出口、同一批程序上完成，只改 4D 布尔注意力掩码。上报任何数字之前，先验证掩码确实传到了 SDPA（显式 full mask 复现无掩码 logits）。

实验日志 — 第 3 周
主题：冻结 Qwen 的注意力可见性实验——把证据留在可见范围内，是否足以保住长距离检索？
计划位置：第 3 周（35 小时）
环境：NVIDIA RTX 4000 Ada（19.5 GB），torch 2.6.0+cu124，transformers 4.57.1，bfloat16；模型 Qwen2.5-Coder-3B-Instruct（36 层，hidden 2,048，16 头 / 2 KV 头），权重冻结；Qwen 分词器随仓库分发；全程不训练。

目标

在权重、提示、数据和答案评分都固定的前提下，测量改变注意力掩码后还剩多少答题能力，判断损失来自"看得少"还是"看的地方不对"，并测量"证据全可见"的 oracle 能恢复多少。

做了什么

1. 门禁（n = 40）：一行算术（trivial）、真实程序 + 注释写出答案（leak）、真实 256 字节程序（real）。通过线：trivial 与 leak 均 ≥ 80%。
2. 第 1 周三跳任务的天花板曲线：96/160/256/512 字节，每类依赖各 20 条。
3. 距离可控生成器：单条依赖链，定义位于目标 token 距离处，填充行按真实分词器标定，标签由第 1 周解释器重算；`--position end` 变体保持长度不变，把定义移到查询紧邻处。
4. 六种可见性，作用在同一条 token 序列上：full；window=W；window=256；random=W（每行同预算、位置随机）；block=4（真切断）；gold_union=W（窗口 ∪ 全部 gold 证据 token 全局可见——使用 gold 标注的 oracle）。
5. 读出口：程序 + `\nprint(result)\n# Output:` + 一个空格 token，再对 10 个数字 token 取 softmax。`# Output: ` 末尾的空格是独立 token（id 25），若直接对数字 token 取 `logits[-1]`，比较的是 `"7"` 而不是 `" 7"`。
6. 测量规模：主表每格 50 条（天花板曲线 20 条），5 个距离；在 1,646 与 4,051 token 上做窗口扫描 64/128/256/512；在三跳数据上做反事实与删除消融。
7. 工程：24 项自动测试，含"显式 full mask == 不传 mask"与"random=W 与 window=W 每行度相同"；一个实验室自检脚本，用随机初始化模型验证 4D 掩码透传。

四点发现。(i) 全注意力下距离不损害能力（73–4,051 token 均为 98–100%）。(ii) **不包含证据的掩码恢复不了，与形状无关；但长距离上两种掩码同处下限、无法区分，这不等于"形状无关"**。近端同预算下窗口对随机是 42:0（p ≈ 4.5×10⁻¹³），原因是窗口恰好包含证据。(iii) 证据全可见在约 450 token 以内可完全恢复，1,646–4,051 只剩 18–22%；同长度、短距离的对照把同一组掩码从 0% 提到 90%（window=64）、从 18% 提到 72%（证据完备性对照），所以衰减由距离造成，与序列长度无关。(iv) 该对照比同宽窗口多用 30–57% 连接，等预算后它在 ≤450 仍显著更好（46:0、41:0），但从 1,646 起与随机基线不可区分（p = 0.11–0.58）；4,051 档 9/3/6 无法分解"0% → 18%"的来源。

另外两个较小的结果：固定结构锚点（每行行首、前 4 token）没有帮助——4,051 token 上行首方案用掉 17.5% 连接、准确率 6%；`gold_union` **不是准确率上界**，近端 72% 低于窗口的 90%。

问题与决定

1. 三跳任务在 3B 上无天花板（15%），不能支撑注意力比较。决定：测一次、作为"难任务切片"报告、主表换到 1 跳距离可控数据。这与第 2 周结尾的"先过门槛"是同一条规则。
2. 4 KB 可见性实验最初跑在三跳数据上，全注意力就只有 3.3%，记为不可解释，改由 4 k token 的 needle 程序替代。三跳数据上的反事实与删除（14.4% / 8.9%）同理。
3. 反事实标签可能超出 0–9，导致 10 路 softmax 越界崩溃。已修：尝试多个增量，只接受重算后仍在 0–9 的改动，否则跳过并计数；加一条覆盖 60 条程序的回归测试，并全量核对 540 条。
4. needle 生成器最初按"每行 7.5 token"估算，但 Qwen 每个数字一个 token，一行约 13 token，目标 4,000 实际生成 6,969。已修：先量一行、直接解出行数、最多四步微调（目标 20/100/400/1,600/4,000 → 66/144/443/1,639/4,044 代码 token）。
5. 未使用 7B：实验室 home 配额只剩 16 GB，而权重 15.2 GB；19.5 GB 显存在 4 k token 上也偏紧。全部结果为 3B，并已如此标注。
6. 掩码不省计算：4D 掩码走稠密 SDPA。逻辑连接数只作为预算口径报告，不写成加速比。
7. `gold_union` 与同宽窗口**不是等预算**：它多用 30–57% 的连接，"0% → 18%"这一步同时改了两个因素。已补 `window=100` / `random=100`（连接数相差 <2%，表 8）。原先"损失来自预算、与位置无关"的说法撤回：长距离格子同处下限，支撑不了这个结论；4,051 档也分解不了两个因素。
8. `random=W` 的种子取自 `crc32(row["id"])`。给 id 加上 `start/end` 后缀后 250/250 条的种子全部改变，已提交的随机数字无法复现。已改为用程序自身的 `seed` 字段加掩码宽度做种子，并重跑了随机条件；重跑时只有 random 列变化，其余模式逐条不变，正好验证了改动范围。
9. 报告曾把 `gold_union` 称为"准确率上界"。近端它 72%、普通窗口 90%（配对 12:3，p = 0.035），这个称呼是错的；它是证据完备性对照。

核验

24 项自动测试通过（因果性、感受野与 BFS 一致、块对角真切断、random 与 window 每行度相同、span→token 映射、数字 token、变异范围、统计函数）。
掩码路径功能性验证：显式 full mask 在 1e-4 内复现无掩码 logits，窗口 mask 会改变 logits。
门禁把"读口坏了"和"任务难"分开：leak 93% 说明可见数字能抄到；real 15% 说明任务本身难。
所有 needle 标签在生成时由第 1 周解释器重算；540 条第 1 周程序在反事实修改后标签仍落在 0–9。
每张表由报告第 7 节的命令产出；逐条记录在 `week3/results/` 随仓库提交；目录与表格的对应关系见 `RESULTS.md`。

2. 转向训练时适配：LoRA 微调 3B，训练时就带 `window=64` / `gold_union=64`，检验 4 k 上的 18% 能否提到 80% 以上。
