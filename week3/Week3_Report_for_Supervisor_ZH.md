# 第 3 周报告：冻结 Qwen 的注意力可见性实验

（面向导师阅读的版本：先讲清每种掩码的原理与一个最小例子，再给实验数据，最后逐表说明"哪张表的哪些格子支撑哪条结论"。）

---

## 1. 一句话结论

在**权重冻结**、提示、程序和答案评分都固定的前提下，只改变"模型能看到哪些 token"，我们发现：

- 全注意力下，答案所依赖的定义哪怕在 **4,051 token** 之外，模型仍答对 **98%**——距离本身不伤能力。
- 把每处可见范围压到 **64 个 token**，准确率掉到 **0–16%**。
- 用**证据完备性对照**（`gold_union`：把所有证据 token 设为全局，使用 gold 标注）在 450 token 以内可完全恢复（98–100%），但在 **1,646 token 以上只恢复到 18–22%**。需要说明：该掩码的连接数比同宽度窗口多 30–57%，所以这一比较**不是等预算**；且它在近端（72%）反而低于普通窗口（90%），因此它只是"信息完备"的对照，**不是准确率上界**。
- 同样 4,051 token 长度、只把定义移到查询紧邻处，同一组掩码从 0% 回到 **90%**——所以失效来自**距离**，不是序列长度。
- 用**可部署的固定结构规则**（每行行首、前 4 个 token）设全局，基本没有帮助：4,051 token 上花掉 **17.5%** 的连接，准确率仍只有 **6%**；而 oracle 只用 4.9% 的连接就有 18%。**结构锚点不等于证据可见。**

**含义**：推理时给稠密模型套稀疏掩码，不能保住长距离检索；要保住，必须在训练时就让模型适应。

## 2. 六种掩码的原理与最小例子

### 2.1 用一个 6 行的程序说明

```
行 1   a = 7            ← 定义（gold）
行 2   b = 3            ← 无关
行 3   c = 9            ← 无关
行 4   d = a - 2        ← 计算（gold）
行 5   e = b + 1        ← 无关
行 6   result = d       ← 查询：模型在这里读答案
```

答案是 5（`7 - 2`）。要答对，模型必须同时用到行 1、行 4、行 6。行 1 与行 4 就是"证据"，在报告里称为 **gold**（由生成器标注，模型输入里看不到这个标注）。

下面所有掩码只改变**每个位置能看哪些位置**，不改变 token 序列本身。

### 2.2 六种掩码在这一小段程序上的效果

| 掩码 | 规则 | 第 6 行（读出口）直接能看到 | 能否答对 |
|---|---|---|---|
| `full` | 每个位置能看自己及之前全部 | 1,2,3,4,5,6 | 能 |
| `window=2` | 每个位置只看前 2 行 | 5,6 | **不能**（缺行 1、4） |
| `random=2` | 每行同样看 2 行，但位置随机 | 例：2,6 | **不能**（缺行 1、4） |
| `block=3` | 每 3 行一块，块内可见、块间永不可见 | 4,5,6 | **不能**（缺行 1） |
| `local_global=2` | `window=2` **∪ 每行行首设为全局**（不看内容，按固定规则选） | 5,6 与行 1、行 4 的**首 token**（`a`、`d`） | **不能**（看得到名字，看不到值） |
| `gold_union=2` | `window=2` **∪ 全部 gold 行设为全局**（按标注选） | 1,4,5,6（整行） | **能** |

这张表就是全部原理（每种模式的论文出处见 §2.6）：

- `window` 与 `random` 是**同等预算**的两种放法（都看 2 行），一个按位置、一个随机；
- `block` 是**真正的切断**：块与块之间连"逐层传递"都没有；
- `local_global` 与 `gold_union` **共用同一个掩码机制**（窗口 + 少数全局），区别只在**全局集合怎么选**：`local_global` 用固定规则（每行行首、前 N 个 token），`gold_union` 用 gold 标注。前者可部署但不知道证据在哪；后者知道证据在哪，因此是上界。
- 这一行的结果不是假设：行内第 3 个字符才是值 `7`，行首全局只露出 `a`。真实实验里同样的现象——4,051 token 上「每行行首」花掉 17.5% 连接、准确率 6%（表 8）。

> 为便于说明，这一节按**行**计数；真实实验按 **token** 计数（一行 Python 约 13 个 Qwen token，因为每个数字单独成 token），规则完全相同。

### 2.3 把程序拉长后

```
行1 a = 7        d01=3  d02=8  ...  d99=2        d = a - 2      result = d
  ↑ 远处定义(gold)       ↑ 100 行无关赋值           ↑ 计算(gold)     ↑ 读出口
  |←———————————————— 约 1,300 token ————————————————→|
```

这时：

- `window=64`：读出口只看得到最后 64 个 token，**行 1 不在其中**。
- `random=64`：看 64 个随机位置，行 1 **大概率不在其中**。
- `block=4`：行 1 与行 6 不在同一块，**永远看不到**。
- `local_global=64`：行 1 的行首被设为全局，但**行首不是值**；行 1 的值在行内第 10 个 token 左右，仍看不到。
- `gold_union=64`：行 1、行 4 **整行**被设为全局，**无论多远都看得到**。

### 2.4 `gold_union` 到底是什么，为什么重要

`gold_union` = "窗口 + 所有证据 token 全局可见"。它做的事是**人为保证信息不缺**：

> 如果答案所需的一切都摆在模型眼前，它还能答对吗？

**先纠正一个称呼。** 早期版本把它称为"准确率上界"，这是不对的：近端对照里它的准确率（72%）低于普通窗口（90%，配对 12:3，p = 0.035）。它保证的是**信息完备**（答案所需的 token 全部可被直接读取），不是**准确率最高**——把 token 设为全局同时改变了注意力形状，本身可能有害。因此本报告改称它为**证据完备性对照（evidence-completeness control）**，"oracle" 只指它用了标注。

它有三点必须说清：

1. **它是诊断对照，不是方法。** 它使用了 gold 标注（哪几行是证据），真实部署时这个标注并不存在。它只回答"信息够不够"，不能当作可用的注意力方案。
2. **它与普通窗口**不只是差在"证据可见"，还差在**连接数**。4,051 token 上 `window=64` 有 257,248 条连接，`gold_union=64` 有 403,867 条（**+57%**）。所以在"0% → 18%"这一步里，证据可见性与连接预算同时变了，**不能把差距全部归因于证据可见性**。要拆开需要预算匹配的对照（`window=100` / `random=100`，约 400,150 条连接），见 §7 第 2 条。
3. **它只能给出一个方向的结论。** 如果 `gold_union` 也恢复不了，说明"仅保证信息可见"不足以恢复能力；但它不能证明"信息不足是唯一原因"，因为该掩码自身可能降低性能（近端 72% vs 90% 就是证据）。

**模型怎么知道哪些 token 是 gold？它不知道。** gold 标注保存在数据集的 `gold_static_spans` 字段里（生成器记录、第 1 周分析器独立复核），与答案同属评测侧信息，不进入提示。构造掩码时，实验代码先把这些字节区间映射成 token 位置，然后只做一件事：把对应位置的布尔掩码置为 `True`。模型收到的只是一个 True/False 矩阵，它无从判断哪些列是证据，只是获得"可以看"的许可。也正因如此，`gold_union` 是实验框架在"作弊"；它不泄露答案（答案 token 不在输入里），但泄露了"哪些位置重要"这一信息。

可部署的替代是第 2 周的依赖分析器：从 `result` 反向遍历依赖边，**不需要任何标注**就能定位证据语句。`gold_union` 相当于把这个预测替换成真值，用来测量"如果预测完全正确，能恢复多少"。

**它与 `local_global` 的区别（只有一个）：全局集合怎么选。** 两者调用同一个掩码构造：窗口 + 少数全局 token（全局 token 可看其前文，也被其后所有位置看到）。差别在于：

| | `local_global` | `gold_union` |
|---|---|---|
| 全局集合的来源 | 固定规则：行首、前 N 个 token | gold 标注：证据语句的 token |
| 需要标注吗 | 不需要 | **需要** |
| 能部署吗 | 能 | 不能 |
| 在本报告中的角色 | 可部署基线（表 8） | 证据完备性对照（表 4、表 7） |
| 连接数（4,051 tok） | 273,190（前 4 token） | 403,867 |

所以它们不是同一个东西：`local_global` 是"一套规则"，`gold_union` 是"同一个机制配上标注"。混为一谈会掩盖本报告最重要的一条对比——**花更多连接、按结构选全局，仍然救不回来（表 8）**。

### 2.5 几个操作定义

- 掩码形状是 4D 布尔张量，`True` = 允许参与注意力，直接传给 `model(attention_mask=...)`。上报数字之前先验证：显式 `full` 掩码与不传掩码的输出在 1e-4 内相等。
- `window=64` 的"64"是 **token 数**，不是行数；在 needle 数据里，一行 `d1234500001 = 3` 约 13 个 token（每个数字单独成 token）。
- 层数 36。窗口掩码在理论上会让信息"逐层接力"：感受野 = 1 + 36 × (64 − 1) = 2,269 token。这是理论可达性，**实测中模型用不上**（见 §4 表 4）。
- 所有掩码下 token 序列完全一致，只有注意力可见性不同。

### 2.6 各模式的文献出处

这些模式不是我们发明的。按导师的要求，这里只引文献综述中已有的四条，其余不再展开。

| 本报告的模式 | 出处 | 原论文中的形态 | 我们的用法与差异 |
|---|---|---|---|
| `full` | Vaswani et al., 2017 [1] | 标准全注意力，复杂度 O(n²) | 作为天花板基线 |
| `window=W` | Longformer（Beltagy et al., 2020）[2] 的 sliding window | 每个位置只看相邻 W 个 token | 相同；未加 attention sink |
| `local_global=W:k` | 机制同 Longformer 的 **global attention** [2]；代码领域的同类设计见 SASA（Liu T. et al., 2022）[4] | 少数 token 设为全局：可看前文、也被其后所有位置看到 | 相同机制；**全局集合按固定规则选**（每行行首、前 k 个 token），不需要标注 |
| `gold_union=W` | **无对应论文**；借用 [2] 的全局机制，全局集合由 gold 标注指定 | — | **oracle 上界**，使用标注，不可部署；与 `local_global` 同机制、不同选法 |
| `random=W` | BigBird 的 **random attention** 组件（Zaheer et al., 2020）[3] | 在窗口之外随机连一部分位置 | 只借"随机位置"这一想法；我们的实现是**与 window 等预算的对照**，不是 BigBird 的完整稀疏模式 |
| `block=L` | **无对应论文**；本项目的固定块对角对照 | 块内全连接、块间不连接 | 仅用于给出"真切断"的下界，不作为某个方法的复现 |

三点说明：

1. **`gold_union` 与 `local_global` 必须分开看。** 两者共用"窗口 + 全局 token"这一机制，区别只在全局集合的来源：一个是 gold 标注（[2] 的机制 + 标注），一个是固定规则（可部署）。前者是上界，后者是基线，见 §2.4 的对照表与 §4 表 8。
2. **`random=W` 是控制变量，不是 BigBird 的复现。** BigBird 的随机连接是其稀疏模式的组成部分；我们的随机掩码严格控制"每行可见数与 window 相同"，只改变位置，用来分离"看得少"与"看错地方"。
3. **文献的共识是"稀疏注意力必须与训练配套"。** Longformer [2] 与 BigBird [3] 都是在训练时就使用各自的稀疏模式；本报告第 4 节的实验正是检验"不训练、只事后改掩码"会发生什么。

## 3. 实验设置

| 项目 | 取值 |
|---|---|
| 模型 | Qwen2.5-Coder-3B-Instruct（36 层，hidden 2,048，16 头 / 2 KV 头），**权重冻结，不训练** |
| 精度 / 设备 | bfloat16，NVIDIA RTX 4000 Ada（19.5 GB），torch 2.6.0+cu124，transformers 4.57.1 |
| 数据 A | 第 1 周的 3 跳程序：256/512/1,024 字节，各 180 条（已通过 2,100 条全量审计） |
| 数据 B | 距离可控的 1 跳程序：单条依赖链，定义放在 20/100/400/1,600/4,000 token 的目标距离外，每格 50 条 |
| 读出口 | 程序 + `\nprint(result)\n# Output:` + 一个空格 token，再对 10 个数字 token 取 softmax |
| 统计 | 每格 50 条（表 2、表 3 为 20 条/格），括号内为 Wilson 95% 区间；**±10 个百分点以内的差异不解释** |

**门禁**：在比较任何掩码之前，先确认读出口没坏——一行 `result = x + y`（trivial）、真实程序 + 注释写出答案（leak）、真实程序（real）。

数据 B 的结构与长上下文评测里常见的"大海捞针"同构：把一行定义放在可控距离之外，再看模型能否取回。区别是这里的答案不是逐字复制，而是**沿依赖链做一次整数运算后输出 0–9 的数字**，因此可以用 10 路读出口给出唯一判定，不需要人工或模型评分。

## 4. 实验数据与逐表结论

### 表 1 门禁（n = 40）

| 级别 | 准确率 | Wilson 95% | 这张表说明什么 |
|---|---:|---|---|
| trivial | 90% | 77–96% | 读出口和提示格式工作正常 |
| leak | 93% | 80–97% | 只要答案出现在输入里，模型能抄到 → 后续掉分不是"读不出来" |
| real | 15% | 7–29% | **3 跳任务本身已接近随机**（10%） |

**结论 1**：管线可信（trivial、leak 都高），但第 1 周的 3 跳任务对 3B 没有天花板，不能用来比较注意力。

### 表 2 三跳任务的天花板曲线（20 条/类）

| 源码字节 | n | 准确率 |
|---|---:|---:|
| 96 | 40 | 23% |
| 160 | 53 | 30% |
| 256 | 60 | 20% |
| 512 | 60 | 7% |

**结论 2**：四个长度全部在 7–30%，没有任何一档可用。在 20% 的基线上比较掩码，得到的差异无法解释。

### 表 3 全注意力下的"深度 × 距离"（n = 20）

| 跳数 | 73 tok | 216 | 736 | 2,816 |
|---|---:|---:|---:|---:|
| 1 跳 | 100% | 100% | 100% | **100%** |
| 2 跳 | 45% | 20% | 20% | 30% |
| 3 跳 | 20% | 5% | 5% | 5% |

这张表的三个格子读出三件事：

- 1 跳那一行**全是 100%**，包括 2,816 token —— 模型完全能处理长距离的单跳检索；
- 2 跳掉到 20–45%，3 跳回到随机 —— **深度才是瓶颈**；
- 因此后续所有实验都换到 1 跳数据，把"距离"单独作为变量。

**结论 3**：深度是瓶颈，距离不是；1 跳任务是合适的实验平台。

### 表 4 六种可见性 × 五个距离（n = 50，1 跳）

| 距离(tok) | full | window=64 | window=256 | random=64 | gold_union=64 | block=4 |
|---:|---:|---:|---:|---:|---:|---:|
| 73 | 98% | 68% | 98% | 80% | 98% | 6% |
| 151 | 100% | 6% | 100% | 12% | 100% | 8% |
| 450 | 100% | 16% | 16% | 8% | 100% | 10% |
| 1,646 | 100% | 6% | 14% | 12% | 22% | 14% |
| 4,051 | 98% | 0% | 12% | 8% | 18% | 4% |

逐列为证：

1. **`full` 列 98–100%**：距离 4,051 也不掉 → 距离本身不损害能力。
2. **73 那行 `window=256` = 98%**：256 覆盖了整段序列，等于 full → 说明掩码确实按设计生效。
3. **151 与 450 两行，`gold_union` 是 100%，而 `window=64` 只有 6%/16%**：在这两档，决定成败的几乎只有"远处定义在不在可见集合里"。**但这一格不是等预算对照**：`gold_union=64` 的连接数比 `window=64` 多 30–50%（151 tok：9,967 vs 7,648；450 tok：40,166 vs 26,784），所以差距里同时包含"证据可见"与"连接更多"两个因素。
4. **1,646 与 4,051 两行，`gold_union` 掉到 22%/18%**：证据已经 100% 可见，仍然答不对（此处连接数也多出 56–57%，所以这个结论更保守：**增加证据可见性 + 更多连接**仍然恢复不了）。
5. **`block=4` 全程 4–14%**：真切断应有的表现。

**结论 4**：≤450 token 时，准确率近似二元——证据可见就对，不可见就错；但这批格子的预算并不相等，见 §7 的匹配对照。**结论 5**：≥1,646 token 时，即使把证据设为全局也只剩 18–22%。

### 表 5 同连接数的局部窗口 vs 随机放置（n = 50）

| 距离(tok) | window=64 | random=64 | 两者连接数 | 配对 McNemar（仅窗口对 / 仅随机对） | p |
|---:|---:|---:|---:|---|---:|
| 73 | 68% | 80% | 2,656 | 7 / 13 | 0.26 |
| 151 | 6% | 12% | 7,648 | 3 / 6 | 0.51 |
| 450 | 16% | 8% | 26,784 | 7 / 3 | 0.34 |
| 1,646 | 6% | 12% | 103,328 | 3 / 6 | 0.51 |
| 4,051 | 0% | 8% | 257,248 | 0 / 4 | 0.13 |

两列连接数**完全相同**，只是一个按位置、一个随机。五档的配对检验都不显著（p ≥ 0.13），但**这不能推出二者等价**：从 151 token 起，两种掩码都处在 0–12% 的下限，在这个区间里任何配对检验都没有区分能力。73 那一档窗口覆盖了几乎整段序列（73 token），两者本就接近。

**结论 6**：在两种掩码**都处于下限**的距离上，它们不可区分；因此这些格子**不能**支持"形状无关"这一说法。它们能支持的只是一条更弱的结论：**不包含证据的掩码，无论形状如何，都恢复不了能力。**

真正把"包含证据"与"形状"分开的是表 6 的近端对照：同样 4,051 token、同样 16 个连接/行预算，`window=64` 与 `random=64` 在 50 道题上分别是 45/50 与 7/50，逐题配对为 **39 : 1**（McNemar 精确检验 p ≈ 7.5×10⁻¹¹）。窗口之所以赢，是因为在这批题里定义恰好落在窗口内——这是"包不包含证据"的差别，不是"局部性更好"的一般结论。

### 表 6 同长度、只改定义位置（n = 50）

| 条件 | 距离(tok) | full | window=64 | gold_union=64 | random=64 |
|---|---:|---:|---:|---:|---:|
| 定义在开头 | ≈4,040 | 98% | **0%** | **18%** | 8% |
| 定义紧邻查询 | ≈46 | 98% | **90%** | **72%** | 14% |

长度、掩码结构、token 总数都不变，只有定义的位置变了。

**结论 7**：4k 上的崩溃由**距离**造成，不是"长序列 + 稀疏掩码"本身。否则两行的 `window=64` 应该是同一个数。

（一个反直觉细节，按配对方式报：距离 46 时 `window=64` 45/50、`gold_union=64` 36/50，逐题配对为仅窗口对 12、仅 gold 对 3，双侧精确 McNemar **p = 0.035**，未做多重比较校正。两组 Wilson 区间重叠并不能当作"无差异"的证据——配对比较才是正确的检验。方向也与直觉相反：`gold_union` 的可见集合是窗口的超集，却没有更好。可能是多出来的全局行稀释了注意力，也可能是小样本波动，暂不下结论；这一格需要在新的 50 题上复核。）

### 表 7 4,051 token 上的窗口扫描（n = 50）

| 模式 | 连接数 | 占 full | 准确率 |
|---|---:|---:|---:|
| full | 8,207,326 | 100% | 98% |
| gold_union=64 | 403,867 | 4.9% | 18% |
| gold_union=128 | 654,651 | 8.0% | 24% |
| gold_union=256 | 1,143,931 | 13.9% | 60% |
| gold_union=512 | 2,073,339 | 25.3% | 78% |

**结论 8**：恢复需要与距离同量级的窗口。4k 距离上要花掉 **25.3% 的连接**才回到 78%；而掩码本身不省计算（见 §5），所以这个比例没有实用价值。

**这张表的局限**：它扫描的是同一个掩码家族（窗口宽度），准确率随连接数单调上升，这一点是干净的；但它**不能用来回答"证据可见性值多少"**，因为 `gold_union=64` 与 `window=64` 的连接数不同（403,867 vs 257,248）。要回答那个问题，需要把 `window` 加宽到与 `gold_union=64` 等预算（`window=100`、`random=100`，各约 400,150 条），见 §7 第 2 条。这个对照目前**尚未运行**。

### 表 8 可部署的固定结构锚点 vs oracle（n = 50）

表 4–7 里除了 `gold_union` 全是"不看内容"的掩码。这一张补上唯一可部署的、利用了结构信息的方案：把某些**位置**固定设为全局（不需要标注）。

| 距离(tok) | full | 前 4 个 token | 每行行首 | 每 4 行行首 | `gold_union=64`（oracle） |
|---:|---:|---:|---:|---:|---:|
| 73 | 98% | 98% | 98% | 98% | 98% |
| 151 | 100% | 6% | 8% | 6% | 100% |
| 450 | 100% | 12% | 12% | 12% | 100% |
| 1,646 | 100% | 12% | 14% | 14% | 22% |
| 4,051 | 98% | 6% | 6% | 6% | **18%** |

连接数对照（4,051 token）：`每行行首` 用掉 **17.5%** 的连接，准确率 6%；`gold_union=64` 只用 **4.9%** 的连接，准确率 18%。**花 3.6 倍的连接，拿到三分之一的准确率。**

原因在机制上：`linestart` 把**行首那一个 token**（变量名的首 token）设为全局，而定义行的值 `7` 在行内第 10 个 token 左右，**不在**全局集合里。也就是说，固定结构锚点暴露的是"名字"，不是"值"。

**结论 9**：固定结构锚点不是 oracle 的可部署替代。它要么覆盖不到值 token（行首方案），要么在证据位于文件前部时无法向前搬运（前 4 token 方案，见 §2.3）。要把 oracle 的优势落到可部署方案上，必须**预测哪些 token 承载值**——这正是第 2 周依赖分析器的职责，而不是任何固定结构规则。

（与文献的关系：SparseCoder 用"标识符的首个子 token"作 identifier attention，解决的是**识别**问题；要**取值**还得看到值本身。这条结果说明两者不能混为一谈，见 §2.6。）

### 表 9 配对检验汇总（逐题，同一批 50 道题）

条件之间是**配对**的（同一道题跑不同掩码），因此用精确 McNemar 检验，而不是比较两个独立的 Wilson 区间。下表只列本文结论真正依赖的比较。

| 数据 | 比较 | 仅前者对 | 仅后者对 | p |
|---|---|---:|---:|---:|
| 近端（gap 46，4,051 tok） | `window=64` vs `random=64` | 39 | 1 | 7.5×10⁻¹¹ |
| 近端 | `window=64` vs `gold_union=64` | 12 | 3 | **0.035** |
| 近端 | `gold_union=64` vs `random=64` | 30 | 1 | 3.0×10⁻⁸ |
| 远端 4,051（start） | `window=64` vs `gold_union=64` | 0 | 9 | 0.0039 |
| 远端 1,646（start） | `window=64` vs `gold_union=64` | 2 | 10 | 0.039 |
| 远端 450（start） | `window=64` vs `gold_union=64` | 0 | 42 | 4.5×10⁻¹³ |
| 恒等验证 | `full` vs `window=256`（151 tok） | 0 | 0 | 1.0 |
| 窗口扫描 4,051 | `gold_union=512` vs `gold_union=64` | 30 | 0 | 1.9×10⁻⁹ |
| 窗口扫描 4,051 | `gold_union=256` vs `gold_union=64` | 21 | 0 | 9.5×10⁻⁷ |

两点说明：

1. **本文共做了约 10 个配对比较，均未做多重比较校正。** 表中 p = 0.035 与 0.039 两处在 Bonferroni 校正后不再显著，只能作为"需要复核"的线索，不能作为结论。
2. `full` vs `window=256` 在 151 token 上完全一致（0:0，p = 1），是掩码接通的恒等验证。

## 6. 有效性威胁

| 威胁 | 影响 | 处理 |
|---|---|---|
| 每格 50 条 | ±10 点以内不可解释 | 全部给 Wilson 区间，跨距离比较不作结论 |
| 只有一个模型规模（3B） | 结论可能只对该尺寸成立 | 明确标注；7B 因实验室 home 配额（16 GB 可用 vs 权重 15.2 GB）未跑 |
| 合成数据 | 与真实代码的距离分布可能不同 | 只称诊断数据；真实代码的距离分布列为下一步 |
| `gold_union` 用了 gold 标注 | 不是可部署方法 | 全表标注为"证据完备性对照"，并明确它**不是准确率上界** |
| **证据可见性的比较不是等预算** | `gold_union=64` 比 `window=64` 多 30–57% 的连接（4,051 tok：403,867 vs 257,248），"0% → 18%"里两个因素同时变 | 已在表 4、表 7 注明；等预算对照（`window=100` / `random=100`）列为下一步第 2 条，**尚未运行** |
| **`random=W` 的掩码此前不可复现** | 原实现用 `crc32(row["id"])` 做种子，而 id 里带 `start/end` 后缀；加入 `--position end` 后 250/250 条的种子全部改变，重跑会得到另一张随机图 | 已改为用**程序自身的 `seed` 字段 + 掩码宽度**做种子（与 id 无关）；但**已提交的 `random=64` 数字需要重跑一次**才能与本仓库当前代码一致。窗口、块、`gold_union`、`local_global` 不受影响 |
| 掩码不省计算 | "连接数"容易被误读为加速 | 统一注明"逻辑连接，非 FLOPs" |
| 未做多重比较校正 | 约 10 个配对比较，p = 0.035 / 0.039 两处校正后不再显著 | 已在表 9 明示；这两处只作"需复核"的线索，不作结论 |
| 配对检验的样本量 | 每格 50 题，15 个不一致对即可让 p 落在 0.03 附近 | 不一致对与 p 值一并列出，读者可自行判断 |
| 第 2 周的两个选择器在本周数据上不可区分 | 250 条 1 跳程序、三个预算下，`structure_topk` 与 `evidence_groups` 选出的块**完全相同**（250/250），因此本周不涉及选择器之间的比较 | 本周只测"信息可见性"，不测选择器优劣；64 字节预算下的 150/250 是**预算可行比例**（d100/d400 的远端证据跨两个 64 字节块，需 128 字节），可行样例上两种方法的完整率均为 100% |

## 7. 下一步

按优先级，前两条是本周结论的方法学补丁，不做完不宜继续外推。

1. **重跑 `random=64`（种子修复后）**：种子已改为与 id 无关，因此表 5、表 6、表 9 中涉及 `random=64` 的数字需要重跑一次才能与本仓库当前代码一致。命令见附录，约 1 分钟。
2. **做等预算对照**：`window=100`、`random=100` 与 `gold_union=64` 在 4,051 token 上连接数都在 40 万左右（`window=100` ≈ 400,150）。三者一比，才能把"证据可见"从"连接更多"里分出来。判读：若 `gold_union=64` 仍明显高于 `window=100`，说明证据位置本身有价值；若接近，则先前"0% → 18%"主要是预算差。
3. **停止调掩码参数**：冻结权重下，长距离损失无法靠"让证据可见"弥补。
4. **转向训练时适配**：LoRA 微调 3B，训练时就带 `window=64` / `gold_union=64`，检验 4k 上的 18% 能否提到 80% 以上。
5. **测 `analyzer_union`，而不是继续比较两个选择器**：把 `gold_union` 的 gold span 换成第 2 周 `analyze()` 输出的 span（同一掩码规则、同一预算），直接量化"分析器不完美"的代价。两个选择器在本周数据上选出完全相同的块（见 §6），继续比它们得不到信息；有信息量的是**分析器 span 与 gold span 的差距**。
6. **统计真实代码的依赖距离分布**：若绝大多数依赖 ≤512 token，"窗口 512 + 少量全局锚点"在实践中就够用——这比"合成任务上无损"更有说服力。
7. **可选的机制探针**：在 `full` 下测量读出口落在 gold token 上的注意力占比随距离的变化，为"看得见但用不上"提供直接证据。
