# 第 3 周实施说明（修订版）：冻结 Qwen 的可见性实验

适用项目：长上下文代码 Transformer 的高效注意力研究。前两周产物见 `report/Week1-2_Experiment_Report_ZH.md`。

**三步的框架是对的**：先定天花板，再把证据映射到模型自己的位置，最后改可见性。但按原稿执行会得到三个无法解释的结果，原因不是你写得粗，而是三件事在真实 tokenizer 和真实模型上不成立。下面每一处都给了实测数字，最后给修订后的执行顺序。

本文所有数字都是在本机用 Qwen2.5-Coder 的真实 tokenizer、真实 0.5B/1.5B 权重跑出来的。**它们是管线验证和量级估计，不是结论**：样本 20–80 条，只够说明"这一步会不会白做"。

---

## 1. 五处必须改

### 1.1 窗口注意力不是信息切断，"可见范围"要先算感受野

原稿默认：窗口 64 就意味着远处的 `v051 = -1` 看不见。不对。每层窗口 64 的因果注意力叠 L 层，最远可见距离是

```
RF = 1 + L × (W − 1)
```

Qwen2.5-Coder-7B 有 28 层，W=64 时 **RF = 1765 个 token**。信息可以靠中间 token 逐层搬运，跟卷积的感受野一样。

用你的测试集和真实 tokenizer 实测（`week3/preflight/preflight.md`）：

| 源码字节 | 条数 | Qwen token 均值 | 证据 token 占比 | 读出口到最早证据的距离 |
|---:|---:|---:|---:|---:|
| 256 | 180 | 203 | 30.8% | 172 |
| 1,024 | 180 | 886 | 6.9% | 703 |
| 4,096（配对加长） | 180 | 3,693 | 1.6% | 2,949 |

"最远证据在 L 层内**根本到不了**读出口"的样例比例：

| 源码字节 | W=8 | W=16 | W=32 | W=64 | W=128 | W=256 |
|---:|---:|---:|---:|---:|---:|---:|
| 256 | 22% | 0% | 0% | 0% | 0% | 0% |
| 1,024 | 98% | 91% | 9% | 0% | 0% | 0% |
| 4,096 | 100% | 100% | 100% | 94% | 9% | 0% |

（7B，28 层；3B 是 36 层，RF 更大，整列更偏向 0%）

**结论**：在 256 B 上，只要 W ≥ 16，就没有任何样例是"信息到不了"的；1 KB 上 W=64 也是 0%。**要在 4 KB 上跑 W=64，窗口才第一次成为真正的信息切断。**

但这里有个反直觉的实测结果，正好说明"改哪里"：

| 1-hop 程序，1.5B，full attention | 距离 73 token | 216 | 736 | 2,816 |
|---|---:|---:|---:|---:|
| 准确率 | 90% | 95% | 95% | 95% |

**只要一跳，2,800 token 的距离完全不伤准确率。** 而同一个模型：

| 1-hop，window=64 | 73 | 216 | 736 | 2,816 |
|---|---:|---:|---:|---:|
| 准确率 | 60% | 5% | 10% | 20% |
| 证据"L 层内可达"比例 | 100% | 100% | 100% | 73% |

窗口 64 在 216 token 上就把准确率打到 5%，**而按 RF 算，那条证据是"可达"的**。所以：

- 可达性是**必要条件**，不是准确率的预测器。真正的断点是"证据能不能被读出口**一步**看到"。
- 你的第 3 步测的是对的事，但不能用"连接数"解释结果，要同时记三个量：允许连接数、L 层可达证据比例、**读出口一步可达证据比例**（`gold_direct_frac`，脚本已实现）。

### 1.2 读分数的位置差一个 token

原稿写"追加 `print(result)` 和 `# Output: `，比较模型给数字 0–9 的分数"。真实 tokenizer 下：

```
"# Output: "  →  ['#', 'ĠOutput', ':', 'Ġ']      ← 末尾空格是独立 token（id 25）
"7"           →  ['7']                            ← Qwen 的预分词把数字切成单 token
" 7"          →  ['Ġ', '7']                       ← 没有 "Ġ7" 这种合并 token
```

所以 `prefix + " " + digit` 之后，`logits[-1]` 的候选**不是数字，是空格**。直接对 10 个数字 token 取 softmax，你比较的是 `7` 而不是 ` 7`，和模型的自然续写不是同一个位置。

正确做法（`w3_core.py` 的 `encode_prompt` 已按此实现）：

```python
ids = tok(prompt_text, add_special_tokens=False)["input_ids"]   # prompt_text 以 "# Output:" 结尾
ids.append(tok.encode(" ", add_special_tokens=False)[0])        # 把空格 token 放进输入
logits = model(input_ids=torch.tensor([ids])).logits[0, -1]     # 在空格之后读 10 个数字
```

实测这个改动是决定性的：

| 1.5B，completion 风格 | trivial（一行算术） | leak（把答案写在注释里） | real（你的 256 B 题） |
|---|---:|---:|---:|
| 准确率 | 100% | 92% | 5% |

`leak` 92% 说明读出口是对的（能抄到可见的数字）；`trivial` 100% 说明提示格式没问题；`real` 5% 说明**是这个任务本身做不了**，不是管线坏了。换 chat 模板做同样的 0.5B 门禁，`leak` 只有 15%、trivial 0%——所以**主表用 completion 风格**，chat 只作鲁棒性检查。

另外一条口径要写进报告：首位数字评分会把模型答的 "10" 记成 1。你的标签是 0–9，错误仍然是错误，但 1 的分数会略偏高；要做错误分析时另跑一遍生成式解码。

### 1.3 主表用 540 条测试集，不用 120 条验证集

原稿用"现有 120 条 256 字节验证程序"。那是第 1 周**选 checkpoint** 用的，每类 40 条，一个格子的 95% 区间宽约 ±15 个百分点。冻结模型没有选模过程，验证集只该用来定 prompt 风格；主表用测试集（每长度 180 条、每类 60 条），并保留三个长度做长度轴。

### 1.4 缺四个对照，差异无法归因

原稿只比较"四种注意力下的准确率"。准确率掉了，你无法区分：证据被切掉了、可见范围太小导致整体退化、还是模型没学过这种 mask。四个对照都很便宜：

| 对照 | 怎么做 | 回答什么 |
|---|---|---|
| `gold_union`（上界） | 窗口 ∪ 全部 gold 证据 token 设为全局可见 | 只保留很少连接、但证据一步可达时，还能剩多少 |
| `block=4`（真切断） | 每 4 行一个块，块间永不可见 | 结构先验本身就够不够（应当是崩） |
| `gold-value`（反事实） | 改 gold 行里的一个整数字面量，标签用第 1 周解释器重算 | 模型是在算，还是在猜格式 |
| `gold-drop`（删除） | 删掉 gold 行，看预测是否改变 | 不用这条证据时答案会不会变 |

实测这四个对照在 1.5B 上的表现（1-hop，20 条/格）：

| 距离 | full | window=64 | window=256 | gold_union=64 | block=4 |
|---:|---:|---:|---:|---:|---:|
| 73 token | 90% | 60% | 90% | 90% | 0% |
| 216 | 95% | 5% | 95% | 80% | 5% |
| 736 | 95% | 10% | 15% | 75% | 15% |
| 2,816 | 95% | 20% | 25% | 45% | 15% |

`gold_union` 在 736 和 2,816 token 两个距离上只用了 full 的 25% 和 7% 连接，把准确率从 10%/20% 拉回 75%/45%，**这才是"高效注意力"故事的主线**：不是"少看一些 token"，而是"少看的时候必须把证据留在里面"。`block=4` 是真信息切断，掉到随机，符合预期。

注意 `gold_union` 在 2,816 token 上只回到 45%：证据一步可见了，但 64 token 的窗口本身还是伤性能。这两个损失要分开报，否则会被审稿人问住。

### 1.5 最关键的一处：你的数据集把"跳数"和"距离"绑死了

原稿问"给足信息时，Qwen 能做对哪几类题"。实测发现这个问法的轴选错了。用真实模型量：

| 依赖跳数（无干扰行） | 1 跳 | 2 跳 | 3 跳 |
|---|---:|---:|---:|
| 0.5B | 95% | — | 5% |
| 1.5B | 100% | 40% | 5% |

| 按 family（1.5B，256 B，full attention） | 赋值链 | 函数调用 | 条件分支 |
|---|---:|---:|---:|
| 准确率 | 10% | 7% | 17% |

**你的三类题都是 3 跳，对 ≤1.5B 全都贴着 10%。** 在这个天花板上比较四种注意力，只能得到"全都是 10%"，和"注意力没影响"没法区分。这不是数据错，是第 1 周任务的难度超过了这个尺度的模型。

而 1 跳的任务给了一个完美的实验平台：**天花板 95%，距离可独立拉长到 2,800 token，而且窗口一改就崩**。所以第 3 周必须把两个因素拆开：

- **深度**（1/2/3 跳）控制"模型会不会做"；
- **距离**（20/100/400/1600 token）控制"要不要跨远距离取证据"。

`week3/w3_needle.py` 已按这个设计生成好数据（`data/needle_test.jsonl`，3 跳数 × 4 距离 × 20 条，标签用第 1 周解释器复核）。原 540 条保留，作为"难任务切片"单独报。

## 2. 修订后的执行顺序

每一步都有 go/no-go。**不达标就停在那一步修，不往下跑**——这是第 1 周已经付过一次学费的地方（基线接近随机时做的比较，数字无法解释）。

### Step 0 · 半天：门禁

```bash
cd week3
python -m unittest -v test_week3                 # 24 项，不需要权重
python w3_gate.py --model <7B 路径> --style completion --limit 40
```

判据（写进报告）：

| 级别 | 含义 | 通过线 |
|---|---|---|
| trivial | 一行 `result = x + y` | ≥ 80% |
| leak | 真实程序 + 注释里写出答案 | ≥ 80% |
| real | 真实 256 B 程序 | 只记录，不作判据 |

`leak` 不达标 = 读口/模板错了，先修，别往下走。实测参考：0.5B 95/100/5，1.5B 100/92/5。

### Step 1 · 1 天：天花板曲线

```bash
python w3_curve.py    --model <7B> --lengths 96 160 256 512 1024   # 现有 3 跳任务
python w3_needle.py   --distances 20 100 400 1600 --hops 1 2 3 --per 20
python w3_run.py      --model <7B> --data-dir data --split needle_test --lengths 0 \
                      --group-by family_id --modes full --no-reach --out results/needle_7b
```

产物：两张表——(字节长度 × family) 准确率、(跳数 × 距离) 准确率。**这是第 3 周真正的主结果之一**：它决定后面用哪个任务配置。

判据：至少有一个 (跳数, 距离) 组合 ≥ 70%。若 7B 在 3 跳 256 B 上仍 ≤ 20%，就把主表切到 1 跳 needle，原数据集降级为"难任务切片"并在报告里说明为什么换。

### Step 2 · 1 天：证据依赖（不是"能不能看到"，是"用不用"）

```bash
# 反事实：改一个常数，标签重算
python w3_run.py --model <7B> --split test --lengths 256 --style completion \
                  --ablate gold-value --modes full --out results/cf_7b
# 删除：证据没了，预测该变
python w3_run.py --model <7B> --split test --lengths 256 --style completion \
                  --ablate gold-drop  --modes full --out results/drop_7b
```

判据：反事实下准确率应基本不掉（说明模型跟着代码走）；删除后与 clean 预测的一致率应掉到 ~10%（说明模型真的在用那条证据）。两个都不满足时，"长距离证据"这个前提本身受质疑，先写清楚再谈注意力。

原稿第 2 步的"把源码范围映射到 Qwen token 位置"不是独立实验，它是这一步和第 3 步的度量基础设施，已经在 `w3_core.span_token_positions()` 里了：**gold 的字节偏移 → prompt 里字符偏移 → token 位置**，测试固定了"每个映射位置确实落在 gold 文本里"。

### Step 3 · 1.5 天：可见性对比

先跑最便宜的四个条件，再决定要不要全量：

```bash
python w3_run.py --model <7B> --data-dir data --split needle_h1 --lengths 0 \
  --group-by family_id --modes full,window=64,gold_union=64,block=4 \
  --out results/vis_7b
```

然后按需扩展：

| 模式 | 定义 | 现在的含义 |
|---|---|---|
| `full` | 因果全可见 | 天花板 |
| `window=W` | 每个位置看前 W 个 | 局部注意力；W 要按 RF 选 |
| `local_global=W:linestart:K` | 窗口 + 每 K 行行首为全局 | Longformer 式；**全局 token 必须夹在证据和查询之间才有用** |
| `block=L` | 每 L 行一块，块间永不可见 | 真切断，结构先验上界 |
| `gold_union=W` | 窗口 + gold 证据全局 | 依赖 oracle 上界，不是方法 |

`local_global` 有个容易写错的点：全局位置若都放在开头（`first:4`），它就是纯读取槽，**无法把证据往前搬运**。实测 4 KB 上 `local_global=32:first:4` 只有 1.9% 连接，但 L 层可达率只有 29–36%。要让它有用，全局集合应该是证据和查询之间的锚点（行首、函数定义行、`result` 行）。

必须同时报的量（`summary.csv` 已含）：

| 列 | 含义 | 为什么必须 |
|---|---|---|
| `accuracy` + Wilson 区间 | 主指标 | n=20/格，5 个百分点以内不可解释 |
| `mean_connections` / 连接占比 | 允许的 (query,key) 对数 | 和 full 对比的"省了多少" |
| `mean_gold_visible_frac` | L 层内可达的证据比例 | **信息论上界** |
| `mean_gold_direct_frac` | 读出口一步可见的证据比例 | 实测里唯一跟随准确率变化的量 |
| 耗时 | 墙钟 | 提前声明：**mask 不会加速**，见 §4 |

判据：`full` 与 `window=256`（当 256 ≥ 序列长度时）应逐条一致，作为 mask 接通的验证；`block=4` 应掉到随机。这两个不成立就是实现错了，不是科学发现。

## 4. 工程细节与已知坑

1. **4D mask 直接传 `model(attention_mask=bool4d)` 就行**。这个 transformers 版本（4.57.1）的 `_preprocess_mask_arguments` 对 4D 输入原样返回，SDPA 收到后 `is_causal=False`，True = 可参与。测试 `test_explicit_full_mask_equals_no_mask` 固定了这一点：显式 full mask 与不传 mask 的输出在 1e-4 内相等。
2. **mask 不加速，先声明**。第 1 周已经测过：逻辑连接降 56.5%–87.9%，稠密 SDPA 的耗时基本不动。第 3 周的耗时列是复现这个结论，不是新结果。真要加速得改执行（块稀疏内核）或减 token（输入选取），那是另一条线。
3. **显存比想象的小**。4D bool mask 走的是 memory-efficient 路径，不会物化 L×L：0.5B 在 3,670 token 上，带 mask 峰值 1.18 GB，不带 1.17 GB。7B（15.2 GB 权重）在 8k 以内可以跑，但仍建议 4 KB 起步。
4. **平台是 AMD（RX 7900 XTX 24 GB，torch 2.10.0+rocm）**，没有 flash-attn，`attn_implementation` 用 `sdpa`；要 `output_attentions` 看注意力质量时必须切 `eager`（sdpa 不支持）。
5. **别改第 1 周的 `dataset.py`**。它的名字池只有 256 个，`make_sample` 在 4 KB 上会 `StopIteration`。加长用 `w3_core.lengthen_program()`：插入无关赋值行、平移 gold 偏移、再用第 1 周解释器复核标签，已有 180×2 条全部通过。
6. **删除 token 会重新分词**。整行删除时换行是独立 token，分词基本不变，但位置会前移；若之后要保留原始位置，必须显式传 `position_ids`。删除和 mask 是**两个机制**，不要混在一张表里比。
7. **算力估算**：0.5B 在 3.7k token 上约 1.5 s/条（含分词、mask、可达性）；7B 约 10–15 倍。540 条 × 5 模式 × 3.7k token 在 7B 上大约是 10–15 小时，**不要一次跑完**：先 80 条筛模式，再全量。
