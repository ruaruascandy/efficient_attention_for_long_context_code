# 第 1 周：一页实验方案

**范围**：在固定的上下文与计算预算下，研究“代码依赖证据组”的联合选择能否改善长上下文代码任务的准确率—成本权衡。

## 1. 研究问题

把相关代码按“依赖闭合的证据组”整体选取，是否比逐块独立选取更好地保留回答问题所需的证据，并在同一个模型上提高答案准确率、降低推理成本？

拆成三个可测的子问题：

1. **选择质量**：预算受限时，组选择是否比逐块选择保留更多完整证据？
2. **任务收益**：固定同一份模型权重，证据组输入是否提高答案准确率？
3. **端到端成本**：加上选择器自身的开销后，是否仍然更省？

## 2. 主任务与边界

| 项目 | 本阶段定义 |
|---|---|
| 输入 | 受限 Python 源码（赋值链、函数调用、条件返回三类依赖） |
| 查询 | 最后赋值语句中变量 `result` 的最终值 |
| 输出 | 0–9 的整数类别 |
| 明确不做 | 任意真实仓库代码、跨文件解析、7B 规模微调（列为后续阶段） |

选择这个任务的理由：标签可以由受限解释器独立算出，不受模型影响；依赖结构可控，能把“选择策略”这一个变量单独拿出来比较。

## 3. 比较方法

同一份 checkpoint、同一批测试样例、同一预算口径下比较：

| 方法 | 依据的信息 | 选择单位 | 角色 |
|---|---|---|---|
| Full | 无预算，全部代码 | 全部块 | 上界参照 |
| Local / Window | 查询块 + 邻近块 | 固定窗口 | 低成本参照 |
| lexical top-k | 与查询的词法重叠 | 单块独立打分 | 弱基线 |
| structure top-k | 依赖图权重摊到块 | 单块独立打分 | 主对照 |
| evidence groups | 依赖闭包成组，按“新完成组权重 / 新增 token”贪心 | 组 | 待验证方法 |
| 学习式路由器 | 训练得到的打分器 | 组 | 后续阶段，本阶段不实现 |

关键对照是 **structure top-k vs evidence groups**：两者使用完全相同的依赖图、候选组和权重，只差“是否按共享成本联合选择”。否则容易把“用到了结构信息”的收益误记成“分组选择”的收益。

## 4. 数据

- **当前数据**：自建受控数据 `week1-v1`，2,100 条（训练 1,200 / 验证 360 / 测试 540），3 类依赖 × 8 个模板，模板 0–3 / 4–5 / 6–7 在三个集合间不重叠。详见 [dataset_card_ZH.md](dataset_card_ZH.md)。
- **性质**：这是诊断数据，**不是 benchmark**。所有结论只在“受限语法 + 合成分布”内成立。
- **分词口径**：UTF-8 字节（1 字节 = 1 token），不是 Qwen / DeepSeek 的 token 数。迁移到其他模型时必须重新分词并重算预算。
- **计划中的真实数据**：LCC-Python（LongCoder 使用的公开代码补全数据）。

## 5. 评价指标

| 维度 | 指标 | 报告方式 |
|---|---|---|
| 答案 | exact-match accuracy | 每个长度 180 条，附 Wilson 95% 区间 |
| 证据 | 静态证据完整率、远端证据召回率 | 按方法 × 预算 × 任务类型分组 |
| 成本 | 输入 token 数、选择耗时、模型耗时、进程 RSS / GPU 峰值显存 | 分开报告，不合并成一个数 |
| 公平性 | 同一 checkpoint、同一测试样例、同一预算 | 训练只用 train/validation，测试只开一次 |

样本量只有 180/长度，1–2 个百分点的差异不作结论；三个种子是三次初始化，不是三份独立数据。

## 6. 对 benchmark 要求的回应

导师关心“用什么 benchmark”。分两层回答，不混为一谈：

1. **现阶段（可行性）**：自建数据只用于验证管线和方法差异，报告中明确标注“非 benchmark”，不外推。
2. **正式阶段**：迁移到 LCC-Python，报告 exact match、编辑相似度，按代码长度和依赖类型分层，并给出同预算下的成本对比。
3. **必须说明的差距**：当前任务是 0–9 分类，LCC 是 token 级补全，输出头、分词、评价指标都要重做，现有数字不能直接搬过去。

## 7. 当前状态与风险

- 基线尚未学会任务：256 字节测试准确率 8.52%，随机期望 10%。**先过“任务学习门槛”，再比较选择策略**；否则是在比较两个都不会做的模型。
- 模板只有 24 个骨架，泛化范围有限；干扰语句主要是简单赋值，不能代表真实仓库。
- CPU 与 GPU 的数字不能混在同一张表里。
